## 1. 项目由来与需求演进史

这一点非常重要：**需求是分多轮逐步追加的**，最终规格 = 各轮需求叠加。按时间顺序：

### 1.1 最初诉求
> 「做一个用于背单词的小程序，需要哪些工具」

用户在纯 HTML 单文件、Python 桌面版、微信小程序三者中**选择了「单文件网页」**（理由是零安装、手机电脑都能用）。

### 1.2 第一版功能规格
> 「根据我提供的词根表编写一个背诵词根和对应单词的小程序。程序分为两种模式：学习模式和测试模式。学习模式通过英文和中文释义来帮助我学习记忆，测试模式则测试我对每种词根的熟悉程度。通过选择题建立单词、词义、词根、词根意义的相互映射。注意要能够按照页码范围自主选择背诵范围」

拆解：
- 两种模式：**学习模式**（英文 + 中文释义辅助记忆）、**测试模式**（考词根熟悉度）
- 测试用**选择题**，建立四者互相映射：**单词 ↔ 词义 ↔ 词根 ↔ 词根意义**
- 能**自主选择背诵范围**

> ⚠️ 注意：最初说的是「页码范围」，但后续提供了 `data.txt` 后，范围的实现载体变成了**字母范围（A–R）**，不是 PDF 页码。这是实际落地的形态。

### 1.3 追加：复习功能
> 「能够在选择了要背诵的页码数后开始记录所学内容并且加上复习功能：根据天数自动设置复习」

→ 落地为艾宾浩斯间隔复习 + 复习计划看板。

### 1.4 追加：完整流程定义
> 「流程：所有卡片都进行翻面学习，然后所有卡片进行第一轮测试；之后是第二轮，第三轮... 而且应当可以自由选择每日背诵个数」

→ 落地为「全卡片翻面学习 → 多轮测试」，并增加「每日背诵个数」设置。

### 1.5 追加：清空进度 + 学习顺序约束
> 「加一个清空进度功能，而且在今日新学完成前不可以学习新单词」

→ **清空进度**：已实现（v1 只有「全部清空」，v2 扩展为「按字母范围重置 + 全部清空」两级）。
→ **「今日新学完成前不要学新词」**：⚠️ **这条并未做成硬性拦截**。当前实现是软的引导——首页「开始今日学习」会把「N 个新词根 + 全部到期复习」合成一个批次一次做完，但用户仍可点「只学新词根」跳过复习。若需要真正的强制拦截，需新增判断（见 §8.2）。

### 1.6 追加：乱序（**上一轮未完成，本轮完成**）
> 「再加上乱序排放功能」

上一轮 AI 因额度耗尽未实现。**本轮已实现**，并经过用户澄清。

### 1.7 本轮（最新）需求 + 用户澄清
> 「添加进度重置功能；并且对基本功能进行改进：对于单词背诵的顺序变为乱序，每次测试的基本轮数变为 3 轮」

用户对歧义点做了明确澄清（**以澄清为准，优先于字面理解**）：

| 澄清项 | 用户原话 | 落地解读 |
|---|---|---|
| 乱序范围 | 「学习内容在我选定范围内（如 a-c）进行打乱（即在我选定范围后生成一个范围内的随机顺序」 | 选定字母范围 → 在该范围内生成**一组**完整随机顺序；学习与测试都按此顺序；**不是**每题独立随机抽取 |
| 轮数规则 | 「至少考三轮，当出现错题加一轮，上限 8 轮」 | **基本轮数 = 3**（第 1/2/3 轮考全部卡片）；第 3 轮后若仍有错题 → **追加 1 轮补考**（只考上一轮错题）；每有错题就再加一轮；**硬上限 8 轮** |
| 重置粒度 | 选择「全部清空 + 按字母段重置」 | 两个入口都要：当前字母范围重置 + 全部清空 |

## 2. 最终功能规格（权威版）

### 2.1 范围选择
- 首页可选**起始字母 / 结束字母**（A、B、C、D、E、F、G、H、I、J、L、M、N、O、P、Q、R，共 17 个字母；**注意没有 K**）
- 可选**每日背诵个数**：数字输入框（1–999）+ 快捷按钮 `10 / 20 / 30 / 50 / 80 个/天`
- 实时显示该范围内「词根数 · 单词数」

### 2.2 乱序机制（v2 新增，核心）
- 每次进入某个范围，在该范围内生成**一个完整的随机排列**（`orderPool`），持久化到 localStorage
- **每日新学**从这个乱序池里按顺序取 N 个未学词根（不是 A1、A2、A3 顺排）
- **学习阶段**的卡片顺序 = 该批次再打乱一次（`startSession` 内 `shuffle`）
- **每一轮测试**的题目顺序都重新打乱
- 换字母范围 → 自动重新乱序
- 首页提供**「重新乱序」**按钮 → 手动重排当前范围
- 重置进度后 → 也重新乱序

### 2.3 学习阶段
- 逐张卡片翻面：**正面** = 词根形式（大字）+ 英文释义；**背面** = 该词根下全部单词 + 词性 + 中文释义
- 卡片顶部标签显示 `X 段 · 第 N 组`（+ 已掌握等级，若有）
- 支持点击卡片翻面、`空格` 翻面、`←/→` 切换、`Enter`（最后一张且已翻面时）进入测试
- 顶部进度条显示 `当前 / 总数`

### 2.4 测试阶段（多轮，v2 修订）
- 第 1～3 轮（`MIN_ROUNDS = 3`）：**每轮都考本次全部卡片**
- 第 3 轮结束后若 `roundWrong.length > 0` 且 `round < 8` → 可进入**第 4 轮「错题补考」**（只考第 3 轮答错的卡片）
- 第 4 轮若还有错题 → 第 5 轮继续（只考第 4 轮错题）…… 直到全对或达到 `MAX_ROUNDS = 8`
- 每轮结束有小结页：正确数 / 总数、答错的词根列表、下一轮按钮 + 「结束并保存进度」
- 判断函数（**关键，别改错**）：

  ```js
  const MIN_ROUNDS = 3;   // 基本轮数
  const MAX_ROUNDS = 8;   // 硬上限
  function roundNo(){ const n = parseInt(S.round,10); return isNaN(n) ? 1 : n; }
  function mustContinue(){ return roundNo() < MIN_ROUNDS; }            // 基本轮数没用满 → 必须继续
  function canContinue(){ return mustContinue() || (S.roundWrong.length>0 && roundNo() < MAX_ROUNDS); }
  ```

  > 历史陷阱：早期版本把条件错写成「只有错题才继续」，导致**全对时第 1 轮就结束**。必须保留 `mustContinue()` 分支。

### 2.5 六种题型
每题 **4 个选项**，四选一，选项顺序随机：

| # | 题型标签 | 题干 | 正确答案 | 干扰项来源 |
|---|---|---|---|---|
| 1 | 词根 → 词根释义 | 词根「X」的含义是？ | 该词根 `meaningEn` | 其他词根释义 |
| 2 | 词根释义 → 词根 | 含义为「Y」的词根是？ | 词根形式串 | 其他词根形式 |
| 3 | 单词 → 中文释义 | 单词「W」的中文释义是？ | 该词中文 | 其他单词中文 |
| 4 | 中文释义 → 单词 | 中文释义「C」对应哪个单词？ | 单词 | 其他单词 |
| 5 | 单词 → 词根 | 单词「W」属于哪个词根？ | 词根形式串 | 其他词根形式 |
| 6 | 词根 → 单词 | 下列哪个单词含有词根「X」？ | 该词根下随机一个单词 | 其他单词 |

- 每张卡片随机抽一种题型
- 干扰项优先取**同字母段**的其他词根（`otherRoots()`），不足 6 个时退回全库
- 选项用 `uniqueOpts()` 做小写归一化去重，保证 4 个选项文本互不相同

### 2.6 记忆模型（艾宾浩斯）
```js
const INTERVALS = [1,2,4,7,15,30];   // 天
```
- 每条记录：`{ level, first, last, next, ok, no }`
  - `level` 0–6，达到 6 视为「已掌握」
  - `next` 是下次复习日期（当天 0 点时间戳）
- **会话结束统一结算**（`commit()`），不是每题即时更新：
  - 本次会话中**从未答错** → `level = min(level+1, 6)`，`ok++`，`next = 今天 + INTERVALS[level-1]`
  - 本次会话中**答错过至少一次** → `level = 0`，`no++`，`next = 明天`
- 复习队列：`dueList()` = 所有 `next <= 今天` 的已学词条
- 复习计划看板：未来 7 天每日到期数量 + 逾期提醒

### 2.7 进度重置（v2 新增）
两个入口，都要有二次确认（`window.confirm`）：

| 操作 | 位置 | 行为 |
|---|---|---|
| **重置当前范围进度** | 首页 + 学习记录页 | 只删除**当前字母范围内**的 `DB.rec` 记录；范围外记录保留；清空 `orderKey`/`orderPool` 并重新乱序 |
| **清空全部学习进度** | 学习记录页 | `DB.rec = {}`，全部重置并重新乱序 |

```js
function resetRange(){
  const ids = new Set(scopeRoots().map(r=>r.id));
  let n = 0;
  Object.keys(DB.rec).forEach(k=>{ if(ids.has(Number(k))){ delete DB.rec[k]; n++; } });
  DB.orderKey = null; DB.orderPool = [];
  ensureOrder(); save();
  return n;
}
function resetAll(){ DB.rec = {}; DB.orderKey = null; DB.orderPool = []; ensureOrder(); save(); }
```
> `scopeKey()` = `from + '~' + to`，用于判断范围是否变化。
> `ensureOrder()` **必须在重新生成顺序后立即 `save()`**，否则刷新页面会重新乱序（这是本轮修复的一个真 bug）。

### 2.8 首页三按钮语义
- `开始今日学习（N 张卡片）` = 乱序抽 N 个新词根 + 全部到期复习（去重）
- `只复习到期（M）` = 只做复习队列
- `只学新词根（N）` = 只学 N 个新词根，不做复习

### 2.9 页面结构
- `view` 状态机：`home` / `session` / `plan` / `records`
- `session` 内部 `phase` 状态机：`study` → `quiz` → `roundend` →（下一轮或）`done`
- 顶部导航：`首页` / `复习计划` / `学习记录`；离开进行中的会话需确认

## 3. 数据规格

### 3.1 `vocab.json` 结构
```jsonc
{
  "letters": ["A","B","C","D","E","F","G","H","I","J","L","M","N","O","P","Q","R"],
  "roots": [
    {
      "id": 1,                                  // 1..342，全局唯一，与 letter/num 无关
      "letter": "A",                            // 首字母（用于范围筛选）
      "num": 1,                                 // 该字母段内的原始编号（来自 data.txt）
      "forms": ["acid","acri","acrid","acu","ac"],   // 词根变体，可多个
      "meaningEn": "sour, sharp",               // 词根英文释义（词库中无中文释义，这是设计关键）
      "words": [
        { "w": "acidity", "senses": [ { "pos": "n.", "cn": "酸度，酸性" } ] },
        { "w": "antique", "senses": [ { "pos": "a.", "cn": "古代的" },
                                      { "pos": "n.", "cn": "古物" } ] }   // 一词多义
      ]
    }
  ]
}
```

### 3.2 实测统计（**准确值，已用 node 校验**）
| 指标 | 数值 |
|---|---|
| 词根组总数 | **342** |
| 单词总数 | **819** |
| 字母数 | 17（`ABCDEFGHIJLMNOPQR`，**无 K**） |
| 一词多义单词数 | 7 |
| `id` 范围 | 1–342，唯一无重复 |

各字母词根数：`A=28, B=7, C=46, D=19, E=10, F=29, G=16, H=15, I=7, J=7, L=31, M=32, N=19, O=11, P=53, Q=4, R=8`

### 3.3 数据来源（重要背景）
- 原始素材有**两份**：一份 PDF《Roots, Prefixes and Suffixes (2026)》（45 页），一份用户旧 Qt 程序的 `data.txt`（826 行）。
- **最终采用 `data.txt`**，因为它结构规整、无需 OCR 纠错；PDF 提取结果（711 条含前缀后缀）**未被采用**。
- `data.txt` 原始行为 7 字段：`字母 = 编号 = 词根变体 = 英文释义 = 单词 = 中文释义 = 词性`
- `data.txt` 只覆盖 **A–R 的词根**，**不含** K 字母、S–Z、以及前缀/后缀（prefix/suffix）。这是词库的天然边界，不是 bug。
- 解析时做了清洗：`\u00a0`→空格、多空格折叠、逗号左右空格规范化（英文用 `", "`，中文用 `"，“`）。

## 5. 本轮（v2）改动清单

### 5.1 新增

### 5.2 修改
1. `beginRound()`：每轮 `shuffle` 队列；`roundQueue()` 第 1–3 轮返回全部 `S.cards`，第 4 轮起返回 `prevWrong`
2. `startSession()`：`cards` 再 `shuffle` 一次
3. `nextBatch() / start-new / start-today`：改用 `pickNew(DB.set.daily)`（乱序抽取）
4. `roundEndHtml()`：区分「基本轮必须继续」与「补考轮」，文案与按钮随之变化
5. `quizHtml()` 标题：改用 `roundLabel(S.round)`（第 4 轮显示「错题补考」）

7. `bindInputs()`：切换字母范围后调用 `ensureOrder()`
8. 标题栏追加「乱序 · 基本 3 轮」
9. **删除**旧的「第二轮起的测试范围：只考上轮错题 / 全部重考」开关及 `DB.set.scope` 字段

### 5.3 本轮修掉的 2 个真 Bug
| # | Bug | 现象 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | 乱序顺序未持久化 | 每次刷新页面都重新乱序，「乱序」形同虚设 | `ensureOrder()` 只改内存不 `save()` | 生成后立即 `save()` |

## 8. 已知限制与后续可做项

### 8.1 词库层面
1. **只有 A–R 的词根**，缺 K、S–Z；**没有前缀/后缀**（虽然原始 PDF 里有）。若要补全，需从 PDF 提取结果（日志中提到有 711 条含词缀的数据，但质量有 OCR 噪声）或让用户提供新的 `data.txt`。
2. 词根**没有中文释义**（`meaningEn` 是英文），所以题型 1/2 是「词根 ↔ 英文释义」。若补中文释义，可增加更贴合中文用户记忆的题型。
3. 少量中文释义在原始数据里就偏短/不完整（如 `domestic` = 「家里的，」结尾带逗号），属于源数据问题。

### 8.2 功能层面
1. **中途退出会话不保存**：`startSession` 会立刻给卡片建档（`level:0, next:明天`），但测试结果只在 `commit()` 时结算。退出=这批卡片算「已学但没测」，明天会进复习队列。
2. **「今日新学完成前不得学新词」未做硬拦截**（用户 §1.5 提过）：目前只是把新词与复习合成一个批次引导，仍可点「只学新词根」跳过复习。若要强制，应在 `start-new` 处理里加判断：若 `dueList().length > 0` 则禁用或提示先完成复习。
3. **补考轮全对后即结束**，即使第 4、5 轮才全对，等级也只 +1（按会话结算）。若想「每轮全对都升一级」需改 `commit()`。
4. 没有**错题本**独立页面（错题只在轮次小结里列出）。
5. 没有**跨设备同步**（纯 localStorage）。
6. 没有**导出/导入进度**功能。
7. 未做移动端专门优化（响应式有基础适配，`@media max-width:600px`）。

### 8.3 建议的下一步（如果需要）
- 优先级高：把 v2 的 `template.html` / `build.mjs` / `test.mjs` 同步到用户原目录，避免误覆盖

- 优先级低：错题本页面、每轮独立升级
